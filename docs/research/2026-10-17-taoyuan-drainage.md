## 0. 一句話結論

**ezdxf 夠用，repo 不夠用。** 排水附圖需要的 CAD 實體 ezdxf 幾乎全有（唯一缺原生 TABLE，可用 TablePainter 替代）；缺的是 repo 這層：排水 schema、圖框/出圖、縱斷面、斷面詳圖模板、水文水理計算、排水 verifier、以及**附來源的桃園法規 yaml**。計算部分幾乎都能寫成確定性純函式，且有官方算例可當測試標準答案。

## 3. 計算方法：可程式化程度

| 項目 | 公式 / 依據 | 程度 | 工程師判斷 |
|---|---|---|---|
| 降雨強度 | Horner I=a/(t+b)^c；桃園手冊表 7-3（中壢/桃園/八德 × 5/10/20 年） | 高 | 選站；**缺 2 年係數** |
| 水保無因次雨強 | 水保技術規範第 16 條 | 高 | 原文係數式網頁亂碼，待核 |
| 合理化公式 | Q=CIA/360（A: ha） | 高 | C 取值 |
| 逕流係數 | 桃園手冊表 7-1（住宅中值 0.79…）；水保第 18 條 | 高 | 範圍內取值 |
| 集流時間 | 桃園建築基地建議 5 min；出流管制 <10 min 以 10 計 | 高 | 流路劃設 |
| SCS-CN、無因次單位歷線、交替區塊雨型 | 出流管制檢核基準第 6–9 點 | 高 | 土壤分類、CN |
| 簡易滯洪檢核 | 0.045（建技 4-3）、0.051 / 0.000014（桃園）、520 m³/ha + 0.16 cms/ha（出流簡易）、安全係數 1.2 | 高 | 適用哪套法規 |
| 曼寧 / 出水高 / 流速 | 桃園手冊：n 表、0.8–3 m/s、出水高 30% ≥20 cm | 高 | n、斷面 |
| 孔口 / 堰 / H-A-V | 桃園手冊 7.7；出流管制手冊附件一 | 高（查圖係數中） | 出流工型式 |
| 動態演算 / 通洪檢核 | 官方指定 SWMM / HEC-RAS 並附輸入輸出檔 | 中（pyswmm）/ 低（HEC-RAS） | 模式建置 |

**可當單元測試的官方算例**：桃園區 t=5 min → I20=161.78 mm/hr；1680 m² 範例 Q20=0.0596 cms、S=90 m³ > 85.68 m³；新北三芝無因次公式 A=16.522、I25=149.27。

## 4. 製圖工具：ezdxf 能力 vs 排水附圖

| 需求 | ezdxf | 備註 |
|---|---|---|
| 圖框 / 多比例出圖 | ✅ paperspace + viewport（實測 1:500 正確） | 縱斷面垂直誇張需自行換算座標 |
| 符號庫 / 圖簽 | ✅ block + ATTDEF | 動態 block 不支援 |
| 剖面填充 | ✅ 172 種 pattern（AR-CONC、EARTH…） | scale 依 $MEASUREMENT，m 圖面要自調 |
| 表格 | ⚠️ 不能建 ACAD_TABLE；TablePainter 用線+字組 | 預覽時文字未顯示，待查 |
| 標註 | ✅ 全類型 | EZDXF 樣式 dimlfac=100 陷阱（已修） |
| 引線 | ⚠️ MLEADER 非 Autodesk 相容差 | 改用 LINE+TEXT |
| 中文 | ✅ TTF；SHX 大字體僅寫入 | 接收端字型才是問題 |
| PDF/PNG | ✅ drawing addon + matplotlib | 避開 PyMuPDF（AGPL） |
| DWG | ⚠️ odafc 需 ODA File Converter；macOS 會跳 GUI；授權待確認 | |
| GIS→DXF | 自寫 shapely→ezdxf | geo addon 不支援 3826 |

**單位衝突**：平面類圖（位置、地籍、集水、排水平面）應採 TWD97 公尺座標（$INSUNITS=6），才能和測量 DXF、審查要求的 TWD97 shapefile 對位；詳圖用 mm。現行 CLAUDE.md「DXF 一律 mm」需修訂為「spec 宣告單位、verifier 檢查一致」。

## 5. 建議方法

```
需求 + 圖資（地籍 GPKG / 建築師 DWG / 測量 DXF）
   │  Agent 寫 DrainageSpec（集水分區 polygon、節點、管段、滯洪池、出流口；不填計算數字）
   ▼
hydro/：rainfall → rational → network(上游累加) → hydraulics(曼寧) → detention(孔口/堰/H-A-V)
   │  所有係數讀 drainage/codes/*.yaml（source/as_of/verified）
   ▼  DrainageResult（每段 Q、V、容量；貯集量；排放量）
render/：common → symbols → gis2dxf / drainage_plan / profile / detail / table → sheet → export(PDF)
   ▼
verify/：drainage_check（拓樸、順坡、通水量≥Q、流速、出水高、0.051/0.000014）
         profile_check（樁號遞增、高程與坡度重算、進出水管高程有標）
         sheet_check（比例尺數值、指北針、圖例、經緯線/座標刻度、圖簽、圖名=統一圖名）
```

**原則**：agent 只描述幾何與拓樸，數字（面積、Q、坡度、體積）全部由程式算、verifier 重算；法規數值只從 yaml 讀。審查常見缺失（§2c）直接變成 verifier 規則。

### 建議開發順序（以「最常被退件」排序）
1. `hydro/` 桃園建築基地流出抑制計算 + yaml + 官方算例測試（純計算，無需改單位規則）
2. `render/profile.py` + `verify/profile_check.py`：**排水縱斷面圖**（最常漏附）
3. `render/sheet.py` + `verify/sheet_check.py`：圖框、比例尺、指北針、經緯線
4. `render/gis2dxf.py` + 集水區分析圖（需先修單位規則）
5. `render/drainage_plan.py` 平面設計圖（標籤避讓是難點）
6. 詳圖模板（U 型溝、筏基滯洪剖面、孔口）
7. 選用：pyswmm 驗算、WMTS 底圖（授權待確認）、DWG 匯入（ODA）
